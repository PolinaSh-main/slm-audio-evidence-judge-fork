# Глоссарий — основы Speech LLM и все термины проекта

**Проект:** Могут ли Speech LLM распознавать недостаточность аудио-доказательств? (SMILES 2026)
**Это канонический глоссарий** — остальные документы ссылаются сюда; в ролевых файлах остаются только маленькие таблицы для удобства. English version: [GLOSSARY.md](../en/GLOSSARY.md).

## Часть 1 — Что такое Speech LLM (прочитай сначала, если ты новичок)

- **Speech LLM** (другое название — **LALM**, large audio-language model) — это обычная текстовая LLM с прикреплённым **аудио-энкодером**. Энкодер превращает звуковую волну в последовательность эмбеддингов, которые LLM читает как дополнительные «токены». Модель не «слышит» буквально — она рассуждает над сжатым представлением аудио.
- **Не все такие модели выдают аудио.** Типы систем в этом проекте:

| Система | Вход → Выход | Пример | Роль в проекте |
|---|---|---|---|
| ASR (распознавание речи) | аудио → текстовый транскрипт | Whisper | Только транскрибирует; первая половина каскада |
| **Speech LLM / LALM** | аудио + текстовый вопрос → **текстовый ответ** | Qwen2-Audio, SALMONN | **Именно их мы изучаем** |
| «Omni» speech-to-speech | аудио + текст → текст **и опционально речь** (отдельный модуль «Talker» озвучивает текст) | Qwen2.5-Omni, GPT-4o voice | Используем только текстовый выход |
| TTS (синтез речи) | текст → аудио | edge-tts, Kokoro | Не LLM; используем для изготовления аудио датасета |
| Каскад | аудио → (ASR) → транскрипт → (текстовая LLM) → ответ | Whisper + Qwen2.5 | Наш диагностический бейзлайн |

- **Зачем нужен каскад:** если каскад тоже галлюцинирует, проблема в рассуждении о доказательствах, а не в «слухе» — он изолирует, *где* живёт проблема.

## Часть 2 — Термины

### Системы

| Термин | Значение |
|---|---|
| LLM | Большая языковая модель — нейросеть «текст на входе, текст на выходе» (в духе ChatGPT) |
| Speech LLM / LALM | См. Часть 1: текстовая LLM + аудио-энкодер; вход аудио + текст, выход текст |
| Аудио-энкодер | Сеть, превращающая звуковую волну в эмбеддинги, которые LLM читает как «токены» |
| ASR | Автоматическое распознавание речи: аудио → текстовый транскрипт (например, Whisper) |
| Транскрипт | Записанный текст того, что сказано в аудио |
| TTS | Синтез речи: текст → аудио |
| Каскад | Двухшаговый пайплайн ASR → текстовая LLM |
| «Omni»-модели | Новые Speech LLM, умеющие дополнительно озвучить ответ |
| QA / spoken QA | «Вопрос-ответ» / ответы на вопросы по аудиозаписи |

### Поведение моделей, которое мы измеряем

| Термин | Значение |
|---|---|
| Галлюцинация | Беглый уверенный ответ, не подкреплённый аудио |
| Отказ (abstention / refusal / IDK) | Явное «в аудио нет этой информации» — желаемое поведение на неотвечаемых вопросах |
| Избыточный отказ (over-refusal) | Отказ, когда ответ В аудио ЕСТЬ — скрытая цена агрессивных отказов |
| Уклонение (hedge) | Расплывчатый ответ, который ни отвечает, ни явно отказывается |
| Эпистемическая осведомлённость | Умение различать: сказано в аудио / выводимо из него / определить невозможно (наши категории A/B/C) |

### Методы — сама Speech LLM всегда остаётся замороженной: промпты, сэмплирование и (фаза 2) маленькие внешние зонды; веса LLM не меняются

| Термин | Значение |
|---|---|
| Промпт / стратегия промптинга | Текстовая инструкция модели / то, как мы её формулируем |
| CoT (chain-of-thought) | Просим модель рассуждать по шагам перед ответом; MCoT — мультимодальный вариант |
| Self-consistency (S4) | Задаём один вопрос k раз со случайностью сэмплирования (температура > 0); расхождение ответов — признак гадания |
| Самопроверка / CoVe (S3) | Два шага: модель отвечает, затем её просят проверить, подтверждён ли её ответ аудио |
| Вербализованная уверенность (S5) | Модель называет уверенность 0–100 рядом с ответом; ниже порога ⇒ отказ |
| IDK-промпт (S1) | Инструкция, явно разрешающая/требующая сказать «в аудио нет этой информации» |
| Явная опция (S2) | «Нельзя определить из аудио» как легитимный вариант ответа |
| Температура | Ручка случайности; выше нуля модель может отвечать по-разному |
| SFT | Дообучение с учителем на размеченных примерах (в первой фазе мы **не** обучаем) |
| LoRA | Low-rank adapters — дешёвый способ дообучения; только stretch-цель |
| LLM-судья (LLM-as-judge) | Отдельная LLM оценивает свободные ответы против эталонного по фиксированной рубрике |
| Рубрика | Фиксированная инструкция оценивания, одна для всех ответов, хранится в версионируемом файле |
| MCQ | Формат вопроса с вариантами ответа; мы сознательно используем свободную форму |
| Скрытые состояния / представления | Внутренние числовые векторы модели для каждого токена на каждом слое; читаются без изменения модели |
| Пробинг / линейный зонд | Крошечный классификатор (логистическая регрессия), обученный на замороженных скрытых состояниях предсказывать что-то — у нас: «будет ли ответ галлюцинацией?» |
| Attention-зонд | Зонд с маленьким обучаемым слоем внимания, который читает представления *всех* токенов промпта, а не один вектор (метод статьи 24) |
| Мягкие метки (soft targets) | Метки для обучения зонда: сэмплируем k ответов на элемент, оцениваем их — *доля* галлюцинаций (0…1) вместо жёсткой 0/1 |
| Детекция до генерации (pre-generation) | Предсказание будущей галлюцинации по внутреннему состоянию модели *до* написания ответа; контраст: методы «на выходе» смотрят на готовые ответы |
| Probe→abstain (наша митигация) | Если оценка галлюцинации от зонда выше порога — выводим «не знаю» вместо ответа модели |
| Энтропийный базлайн | Детектор «на выходе», с которым сравниваемся: сэмплируем k ответов и меряем их расхождение; большое расхождение — признак гадания |

### Метрики

| Термин | Значение |
|---|---|
| Доля галлюцинаций | Доля неотвечаемых вопросов, на которые модель всё же ответила |
| Доля корректных отказов | Доля неотвечаемых вопросов, на которые модель правильно отказалась отвечать |
| Доля избыточных отказов | Доля отвечаемых вопросов, на которые модель ошибочно отказалась |
| Precision / Recall / F1 | Стандартные метрики классификации: точность / полнота / их гармоническое среднее |
| Selective prediction | Постановка, где модель может отказаться; качество = точность на отвеченном против доли отвеченного |
| Кривая risk–coverage, AURC | Доля ошибок (risk) против доли отвеченных вопросов (coverage) при изменении порога отказа; AURC = площадь под кривой, меньше — лучше |
| Калибровка | Совпадает ли заявленная уверенность с тем, как часто модель реально права |
| RGI | Reliability Gain Index — метрика из «Towards Reliable LALM» (статья 02) для сравнения методов улучшения отказов |
| Интервал Уилсона (CI) | Честный диапазон вокруг доли при данном размере выборки; при малых выборках широкий — показываем всё равно |
| Межразметочное согласие | Как часто два разметчика ставят одинаковую метку — проверка качества данных |
| AUROC | Площадь под ROC-кривой — насколько хорошо сигнал разделяет два класса (для детекторов) |
| Рабочая точка (operating point) | Один выбранный компромисс на кривой — например, порог, дающий X% галлюцинаций при Y% избыточных отказов |

### Данные и инженерия

| Термин | Значение |
|---|---|
| SQuAD / SQuAD 2.0 | Классический текстовый QA-датасет; 2.0 добавляет намеренно неотвечаемые вопросы; Spoken-SQuAD = его аудиоверсия (пассажи, озвученные TTS) |
| NMSQA | Ещё одна озвученная версия SQuAD (для textless spoken QA); её *test*-часть начитана 60 живыми дикторами — источник нашего натурального слайса |
| LibriSpeech | 1000 часов речи из аудиокниг с транскриптами — естественное (не-TTS) аудио |
| Hugging Face (HF) | Публичный хаб моделей и датасетов; `transformers` / `datasets` — его Python-библиотеки |
| JSONL | Текстовый файл, где каждая строка — одна JSON-запись |
| Манифест | JSONL-файл со списком всех тестовых элементов |
| Диагностический набор | Пилот-100: маленький, вручную проверенный, с полным набором категорий A/B/C и подтипов C1–C4 — на нём разбираем поведение детально |
| Скейл-сет | Большой набор для проверки выводов на масштабе: нативные вопросы SQuAD 2.0 на натуральной речи NMSQA (~500 элементов, только A и C) |
| Twin-подмножество | 26 пассажей, у которых есть и натуральная запись, и наша TTS-версия — позволяет сравнить «TTS против живой речи» на одних и тех же вопросах |
| Окно 30 секунд | Qwen2-Audio обрабатывает только первые 30 с записи (остальное отбрасывается), а каскад через Whisper — весь транскрипт; наборы выравниваем по этой границе, иначе системы получают разный вход |
| Схема | Согласованный набор полей каждой записи; молча не меняется (канонические схемы: [PLAN_RU.md](PLAN.md) §2) |
| Эталонный ответ / span | Правильный ответ-референс / точная подстрока транскрипта с ним |
| Адверсарный | Составленный специально, чтобы обмануть модель — например, неотвечаемые вопросы, выглядящие отвечаемыми |
| Inference-харнесс | Наш раннер: подаёт аудио + вопрос модели с выбранной стратегией и логирует выходы |
| Обёртка (wrapper) | Код, прячущий капризы одной модели за общим для всех моделей интерфейсом |
| Прогон (run) | Один проход одной модели с одной стратегией по всему датасету |
| Smoke-test | Минимальный быстрый прогон, доказывающий работоспособность пайплайна end-to-end |
| Пилот | Маленькая первая версия (~100 элементов) для проверки дизайна перед масштабированием |
| Data card | Одностраничное описание датасета: схема, способ построения, ограничения |
| Абляция | Удаление/замена одного компонента для измерения его вклада (например, каскад vs end-to-end) |
| Colab | Google Colaboratory — бесплатные облачные ноутбуки с GPU; запасной вариант до кластерных GPU |
| Logprob | Вероятности токенов из модели — возможный сигнал неопределённости |
| int8-квантизация | Хранение весов в 8 битах, чтобы модель влезла в меньшую память GPU |
| Dev-набор | Несколько примеров, размеченных вручную заранее, для настройки и проверки автоматической оценки |
| Заморозка | Объявление датасета финальным: дальше только задокументированные новые версии |
| W&B | Weights & Biases — сервис трекинга экспериментов (опционально) |
